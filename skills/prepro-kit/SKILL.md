# Pre-pro kit

Read the reference for the requested artifact. Consult an earlier stage only when its decisions are missing and the requested work depends on them.

| Mode | Job | Read |
| --- | --- | --- |
| `brief` | Define the project problem, audience, message, deliverables, and constraints. | [Creative brief](references/brief.md) |
| `treatment` | Propose a creative direction that answers the brief. | [Treatment](references/treatment.md); use [creative brief](references/brief.md) if no usable brief exists. |
| `script` | Write a two-column audio and video script from the chosen direction. | [AV script](references/script.md); consult the treatment or brief as needed. |
| `breakdown` | Turn a direction or script into a shoot, asset, and edit plan. | [Breakdown](references/breakdown.md); consult upstream material as needed. |
| `paperwork` | Draft the commercial or rights document needed at this stage. | [Paperwork](references/paperwork.md). |
| `full` | Build a connected preproduction package. | Read the references as each stage becomes relevant. Read [paperwork](references/paperwork.md) before deciding which business or rights documents apply. |

An explicit mode wins. Otherwise select the smallest mode that answers the request. Existing project context can supply upstream decisions without a separate document. If the user gives no project or deliverable, ask what they are making and which output they need.

## Establish the project record

Inspect supplied project files, client material, existing decisions, and approvals. A new project can start from an idea alone. Keep one compact record of the client and project, problem, objective, audience, message and proof, deliverables and channels, budget and timing, assets, decision-makers, rights, and constraints.

Mark material facts `confirmed` when supported by the user's instruction or an approved source, `proposed` when you recommend them, and `unknown` when evidence is missing. Record the source of consequential facts and surface conflicts. Verify restrictive words such as `only`, `must`, and `excluded` against the source; an available resource is not necessarily the only permitted option. Approval requires evidence, including when an asset or earlier draft is available.

Ask about gaps that would change direction, price, obligation, permission, or deadline. For other gaps, state an assumption or leave the field unresolved. This stage is complete when the requested scope and material assumptions are recorded and consequential conflicts are visible. Carry that record through the chosen modes.

## Produce the requested artifacts

Follow each mode's reference for document structure and quality checks. For client-review or full packages, create actual reviewable files when a writable project location is available. Read [Branding and delivery](references/branding-and-delivery.md) for format selection, brand application, and visual inspection. Honor requested formats and locations and save versions that preserve earlier work.

### Full package

For `full`, establish or normalize the brief, develop a treatment, write a two-column AV script for video deliverables, and turn the work into a breakdown. If the scope includes email, a landing page, or other non-video pieces, define their role and content requirements in the brief and treatment. Draft their copy only when requested; do not force it into an AV script. The AV script can be beat-based when runtime is provisional, but it must show planned picture and sound.

Check which paperwork matters now. A planned shoot or use of people, locations, music, or client assets may need a rights checklist; missing permissions make it provisional, not irrelevant. When scope needs costing but rates are missing, use an unpriced estimate structure rather than omitting cost planning. Do not manufacture an invoice or agreement merely to fill a package. Stop before making a consequential legal or financial choice that cannot be grounded in supplied terms.

If essential strategic inputs are missing, produce a working brief with explicit decisions. The user may request provisional downstream drafts; carry the same assumptions through them. Check explicit claims and implied product benefits across video, email, and web against supplied evidence and mark unsupported material for review.

## Complete the handoff

Apply the requested modes' quality checks and reconcile deliverables, dates, fees, revisions, and usage across the artifacts and project record. Completion requires the requested artifacts or a stated limitation for each blocked output, plus the review required for any formatted files.

For multiple artifacts, provide a short manifest with each output's status, saved location, and blocking input. Use `working draft`, `client review`, `pending input`, or `not applicable`; use `approved` only with evidence. Explain omissions and identify the decisions needed next. For a single artifact, state those details with its handoff. Report saved files only when they exist.

This skill stops at preproduction. Source-media selects, editing, final-cut review, signing, sending documents, and collecting payment require their own request. If the project includes AI-generated media, the breakdown specifies shot intent, reference needs, and clearance questions. Generate media only when requested.
