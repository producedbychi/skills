# Branding and delivery

Use this reference when producing files for review, approval, or handoff. A document's content status and its presentation are separate: a polished layout does not turn a working draft into an approved document.

## Choose the identity

Inspect approved brand guides, document templates, logos, font files or font names, color values, and prior approved examples in the project or a user-specified brand folder. Identify which organization should appear on each artifact. A client-facing creative treatment may use the client's brand; an estimate or invoice may use the producer's business identity. Ask when ownership is unclear. Do not place client or business assets, private terms, or font files in this public skill.

Apply a supplied template before inventing a layout. Otherwise use confirmed typography, colors, logo variants, spacing, and usage rules. Keep source paths and approval status clear. An available logo or font is not necessarily approved for this project. If brand material is missing, use a restrained neutral layout and state what is needed to brand it. Do not guess a brand's hex codes or recreate its logo. If a font is unavailable or cannot be embedded or shared, use an approved fallback or flag the substitution.

## Pick a review format

Follow an explicit user or client requirement first. Otherwise choose the format that fits how the reviewer will read, comment, and approve the artifact. These are starting points, not fixed rules:

| Artifact | Useful review format |
| --- | --- |
| Creative brief or scope of work | DOCX for tracked edits; PDF for a stable approval copy. |
| Visual treatment | PPTX when images, frames, or concept comparisons drive the decision; a designed PDF or DOCX when the treatment is mainly prose. |
| AV script | Editable DOCX with a readable two-column table; PDF when a fixed circulation copy is needed. |
| Shot list, production breakdown, or rights register | Spreadsheet when rows need sorting, ownership, or status updates; PDF for a fixed review snapshot. |
| Estimate or invoice | Approved company template when supplied; PDF for a fixed client copy, with an editable source retained when practical. |

Choose one primary review file per artifact. Provide an editable source as well when the reviewer needs to revise it or when future rounds are expected. Do not make duplicate formats that serve no review need. For a full package, the files may use different formats. Keep their titles, versions, statuses, dates, and approval requests consistent.

When the user asks for a client-review or full package and a writable location exists, create the actual files. A Markdown draft or text pasted in chat is appropriate for quick drafting or when requested, but it is not a stand-in for a formatted approval document. If the needed file-generation capability is unavailable, say so and provide the best usable source file rather than naming a nonexistent PDF, DOCX, or PPTX. Do not send files or represent them as approved without authorization and evidence.

## Check before handoff

Render or open each formatted file and inspect every page or slide. Check readable hierarchy, brand colors and fonts, logo clarity, contrast, margins, page breaks, cropped images, table overflow, and legibility at normal viewing size. Verify that the exported PDF or presentation matches its editable source. Confirm that all fields, claims, prices, rights, and approval status match the underlying draft. Fix presentation faults before showing the file to the user. If visual inspection is unavailable, disclose that limitation rather than claiming the file is ready to send.
