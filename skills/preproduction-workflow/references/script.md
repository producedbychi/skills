# AV script mode

An AV script turns the treatment's story into an edit plan before anyone builds the shot list. Use it when the user asks for a script or when `full` calls for one. If the user supplies a script, preserve its approved message and revise or format it as requested. Do not replace an approved script with new copy without asking.

## Write the script

Read the brief and treatment when available. Identify the deliverable, target audience, intended runtime, placement, core message, required claims, call to action, and any approved voice or dialogue. If no treatment exists, write from the supplied concept and mark creative choices `proposed`. Ask about a missing decision only if it would change the message or structure. Otherwise draft with a visible assumption.

Use a two-column table. Keep picture, on-screen text, and graphics in **Video**; keep dialogue, voiceover, natural sound, music, and silence in **Audio**. Put the beat ID and approximate time at the start of each Video cell. If the target runtime is unknown, use beat order and label timing provisional rather than inventing a length.

| Video | Audio |
| --- | --- |
| B01, 0:00-0:03. Action, framing, on-screen text, or graphic needed for the opening. | Exact approved or proposed spoken words; natural sound, music, or silence. |

Write spoken words as speakable copy, not a description of what the narrator might say. Distinguish exact dialogue from direction for a performer. Use sourced product facts and claims only; label unverified claims for review. Do not use an on-screen title or logo as a substitute for the story beat it must support. Show what the viewer understands if they watch without sound, and what audio adds when sound is on.

For several deliverables, write the main version and note the specific changes needed for each cutdown, crop, language, or call to action. Do not claim one master script covers every format if a shorter version loses the opening, message, or payoff. Keep the script producible with known people, products, locations, and assets. Mark anything that requires capture, licensing, generation, or client supply so the breakdown can plan it.

## Handoff and quality check

End with the target runtime and estimated script length if timing is known, required assets or performances, alternate-version changes, and open approvals. Use stable beat IDs so the breakdown can trace each shot or asset back to the script.

- Does the opening establish a reason to keep watching within the intended format?
- Can a producer tell what appears and what is heard at each beat?
- Are spoken words, screen text, claims, and call to action consistent with the brief?
- Can the planned beats fit the runtime without rushing essential information?
- Does the script work within the supplied production limits, with unresolved needs visible?
