# Preproduction workflow

Coordinate the work without duplicating the specialist skills. Each child skill also works on its own.

## Route the request

- For the concept and creative direction, read [creative-brief-to-treatment](../creative-brief-to-treatment/SKILL.md).
- For shots, resources, dependencies, and handoff, read [project-breakdown](../project-breakdown/SKILL.md).
- For estimates, agreements, releases, rights, change orders, or invoices, read [project-paperwork](../project-paperwork/SKILL.md).

Read a child's full `SKILL.md` before doing that part of the work. Load only the children the request needs. If a child is not installed beside this skill, identify the missing skill and complete only the parts that remain supported.

## Shared project facts

Inspect the brief, project folder, brand material, supplied references, and existing approvals before asking questions. Carry one compact set of facts between children: client and project name, objective, audience, deliverables and channels, constraints, dates, budget information, supplied assets, decision-makers, and approved or unresolved terms. Mark each material fact as confirmed, proposed, or unknown. Do not turn an assumption in a treatment into a contractual fact.

For a full preproduction request, work in this order:

1. Develop the treatment and seek a decision on the direction when that decision changes the plan.
2. Break the chosen direction into an executable plan. If the direction is not approved, label the breakdown provisional.
3. Prepare only the paperwork the project calls for. Check its scope, deliverables, dates, fees, and rights against the plan. Draft terms are not signed terms.

Do not force all three stages into a narrow request. Do not generate an invoice merely because a project exists. Finish with the outputs, decisions still needed, and any missing assets, permissions, or approvals.

Source-media selects and final-cut review belong to later stages. Do not present them as completed preproduction work. If the plan calls for AI video, hand the approved shot information to a suitable video-generation skill when that work is requested; do not generate shots by default.
